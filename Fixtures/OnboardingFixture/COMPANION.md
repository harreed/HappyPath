# Companion service experiment

`CompanionServiceTests.testServe` is an XCTest command service. It has no onboarding sequence. The Mac `companion-experiment` executable sends individual version-1 requests through the runner app's `Documents/CompanionMailbox` directory. `CompanionBridge` conforms to `AccessibilityBridging`.

The runner permits the bundle named by `COMPANION_TARGET_BUNDLE_ID`; it must be explicitly configured. The `CompanionService` scheme enables the service and selects the controlled fixture; the normal scheme skips the service. To configure another bundle through xcodebuild, export `TEST_RUNNER_COMPANION_TARGET_BUNDLE_ID` before invocation. A bounded `launchArguments` request field passes arguments to the target without interpretation. The driver's fixture-only `--bridge-probes` launch argument exposes two harmless identically identified probe buttons. The normal baseline fixture has no probes.

Build with the CompanionService scheme and run only `FixtureUITests/CompanionServiceTests/testServe`. Resolve the runner data container using `xcrun simctl get_app_container DEVICE dev.agentic.FixtureUITests.xctrunner data`. Pass its `Documents/CompanionMailbox` path to the Mac driver, followed by an artifact output directory and repeat count. Coordinate one service/driver pair and recording process per Simulator.

The service lives at most 15 minutes and acknowledges explicit shutdown. Requests have unique IDs, session IDs, deadlines, allowed operations and bounded fields. The service reads at most 32 KiB per request, processes at most 32 files per poll, and ends after at most 2048 requests. A decodable correlation envelope with an unknown operation receives a typed invalidRequest response. The `--scroll-probe` launch mode exposes a real ScrollView (`fixture.scroll`), first row (`fixture.scroll.first`) and row 20 (`fixture.scroll.target`) for independent swipe checks. Atomic JSON files bind responses to request and session IDs. Unknown executable content is never evaluated. Snapshots bind screenshot pixel dimensions and the full-screen point frame to a caller-provided immutable capture ID. Alert context comes from snapshot tree ancestry; button roles unavailable through XCTest remain unknown. Same-identifier ancestor wrappers are omitted; multiple leaves remain ambiguous.

Point taps accept only finite in-bounds coordinates from the current unconsumed image, younger than 10 seconds, with an unchanged full-screen frame. Mutations and waits invalidate the prior image. This is a bounded experiment, not proof that arbitrary asynchronous app changes cannot occur between capture and dispatch.

Timeout, cancellation, malformed or mismatched replies and session loss poison the client. A session-specific stop marker asks the service to stop after the current call returns. Dispatch rechecks deadline/poison state after target resolution and between focus and text entry. XCTest/OS calls are not preemptible: an in-flight call may finish after the deadline. Such a session must not be resumed or retried; a supervisor may need to stop the runner if XCTest never returns. The marker write is best effort when filesystem access itself fails; local client invalidation remains mandatory.

The repeat driver retains per-operation events, canonical snapshots, source images, expected rejection evidence, OCR locations and independent semantic final-name assertions. Ten repetitions cover six recorded state kinds (launch, focused, typed, alert, OCR source, complete); image-count or hash diversity is not evidence of fifty different UI scenarios. `--negative-probes` adds explicit malformed/ambiguous/disabled/missing requests, waits, scroll and timeout-poison checks. Video and fresh-runner startup timing are recorded separately. `Scripts/benchmark_ocr.swift` reports first-process request and repeated OCR timing, with OS/model-cache limitations explicitly retained.

Live results belong in phase evidence; source implementation alone does not establish the experiment passed.
